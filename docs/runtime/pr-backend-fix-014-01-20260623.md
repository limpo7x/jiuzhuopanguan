## 合同选择

沿用仓库 `sendError(response, status, message)` 错误格式：

| 请求 | 结果 |
| --- | --- |
| 无 `sessionId/inviteCode` | `400 sessionId or inviteCode required`；不读取默认聚会 |
| 有 `sessionId`、无有效 token | `401 unauthorized` |
| 有 `sessionId`、token 用户非成员 | `403 not session member` |
| 有 `sessionId`、token 用户为成员 | `200`，保留现有成员私有视图 |
| 同时有 `sessionId + inviteCode` | 按 `sessionId` 私有读取处理，仍强制 token 与成员校验 |
| 仅有 `inviteCode`、匿名或非成员 | `200`，仅返回邀请加入所需公开字段 |
| 仅有 `inviteCode`、当前用户为成员 | `200`，保留现有成员视图 |

仅 `inviteCode` 的判定采用 fail-closed，并针对每个实际即将返回的 `liveSession` 重新计算。只有 app_store session 存在、viewer 是该 session 成员、返回 session 的 `id/partyId` 与 app_store 一致、请求/返回/app_store 的 inviteCode 三方一致时才允许成员私有视图；任一条件不满足均返回公开白名单裁剪。

匿名邀请码响应采用严格字段白名单：

`hostName/id/inviteCode/joinedCount/partyId/playerCount/sessionName/stateText/status/subtitle/templateImageUrl/templateName/title`

明确不返回 `hostProfileId`、成员数组、头像、照片、时间线、`visibleNodes`、`ledgerSummary`、分享内容过滤等私有字段；不再通过空字符串或空数组保留这些字段占位。

## 改动

- `backend/server.js`
  - 无参数请求在进入 normalized/app_store 读取前直接返回 400。
  - 只要存在 `sessionId` 就执行用户会话与成员校验，修复 `sessionId + inviteCode` 绕过校验的问题。
  - `inviteCode` 匿名响应改为严格白名单裁剪。
  - app_store 无法确认邀请查看者成员身份时默认公开裁剪，修复 normalized 命中时的 fail-open 边界。
  - normalized/app_store 的 session ID 或 inviteCode 映射不一致时默认公开裁剪，禁止把另一条 normalized session 作为成员私有视图返回。
  - normalized 与 app_store 两条读取路径共用相同鉴权和裁剪决策。
- `backend/scripts/smoke-live-session-privacy.js`
  - 新增独立本地 HTTP smoke。
  - 覆盖无参匿名、匿名 `sessionId`、非成员 `sessionId`、成员 `sessionId`、匿名混合参数、匿名 `inviteCode` 裁剪、成员 `inviteCode`。
  - 直接执行 `getInviteLiveSessionAccess()`，覆盖完全一致允许 private、session ID 不一致、inviteCode 不一致、app_store 缺失均为 public；不再使用源码字符串断言。
  - smoke 强制关闭 MySQL/normalized 读写，使用唯一 marker，并在 `finally` 定向清理用户与聚会数据。
  - 使用操作系统分配的动态空闲端口；启动探测绑定本次 child 生命周期，child 提前退出即失败，不会把旧服务误认为本次服务。
  - `stopServer` 对已退出 child 直接返回，并在终止前注册 `exit` 监听及超时兜底，避免永久挂起。
  - 通过排他锁串行化对共享 JSON store 的临时写入；并发启动的 smoke 会等待前一轮清理完成，避免读改写竞争重新带回另一轮 marker。
  - 获得锁后先定向清理 `live-privacy-/privacy-smoke` 旧 marker，处理异常中断留下的测试用户。

### Smoke 生命周期与串行复跑

PM 复核指出固定端口可能误连旧进程、已退出 child 可能在 `stopServer` 永久等待。第一次并发双跑还暴露共享 `social-store.json` 读改写竞争，并留下 stamp `1782222609946` 的 3 个测试 profile，因此该次并发证据已作废，不作为验收依据。

已按唯一 stamp 定向清理，未执行 `git restore/reset`：

```text
stamp=1782222609946
profileIds=user-1782222609948-5618ef,user-1782222609948-41fb87,user-1782222609947-92c457
profileCount=3
sessionCount=0
SOCIAL_ADMIN_MARKERS_CLEAR
```

脚本现使用动态端口、child 提前退出检测、有限等待 stop、共享 store 排他锁和 stale-marker 定向清理。按 PM 要求不再并发执行共享 store 写测试，改为连续串行两次：

```text
RUN_1: exit=0, ok=true, port=10048
RUN_1_MARKERS_CLEAR / RUN1_PORT_10048_CLEAR / RUN1_LOCK_CLEAR
RUN_2: exit=0, ok=true, port=8719
FINAL_SOCIAL_ADMIN_MARKERS_CLEAR / FINAL_SMOKE_LISTENERS_CLEAR / FINAL_LOCK_CLEAR
```

两轮均完整返回 `anonymousDefault=400 / anonymousDirect=401 / outsiderDirect=403 / memberDirect=200 / anonymousInvite=public allowlist`。后续新增的可执行策略用例还要求 `normalizedAppStoreIdentityMismatchDefaultsToPublic=true`。

接口联调退回 normalized/app_store 身份映射边界后再次完整复跑：

```text
exit=0, ok=true, port=6278
normalizedAppStoreIdentityMismatchDefaultsToPublic=true
```

该结果来自实际执行策略模块，不是源码字符串匹配；同时保留 HTTP 路由原有状态矩阵。
