## 功能验收

- `app_store` 拆表后，高频对象读写路径仍可完成核心业务：创建聚会、加入聚会、上传照片、结束聚会、个人中心摘要、后台聚会管理。
- `/uploads/` 替代方案生效后，图片上传、访问、分享图引用、相册展示使用正式对象存储或 CDN URL；不得继续依赖本机临时 `/uploads/` 作为正式链路。当前仅 CDN/OSS 基础链路通过，业务链路待后端上传接口接入后复测。
- 后台密码重置可由授权管理员完成；重置后旧密码不可登录，新密码可登录，并有操作日志。
- 后台登录失败限制生效：连续失败达到阈值后应被限制，正确密码在限制期内不得绕过；限制解除规则清晰可验证。

## 接口验收

- 后端需提供可复跑接口清单、请求示例、响应样本和错误码说明，覆盖新实体表读写、上传 URL 生成/回源、后台密码重置、登录失败限制。
- 接口联调需提供 `api.pomer.cn` 只读或受控测试证据；如需写入测试数据，必须说明目标环境、样本 ID、清理方式和残留扫描结果。
- 所有接口需验证鉴权边界：未登录、普通用户、管理员、错误 token、过期 token 的返回不能混淆。
- 不接受只给本地函数调用结果、无 HTTP 层证据的接口通过结论。

## 数据迁移验收

- DBA/后端需提供迁移前后数量对账：旧 `app_store` 高频对象数量、新实体表记录数、失败/跳过原因。
- 迁移必须可重复执行或具备幂等保护；重复执行不得产生重复记录、覆盖错误数据或破坏关联关系。
- 抽样验证需覆盖至少：进行中聚会、已结束聚会、照片/相册、分享图任务、后台管理关联字段。
- 迁移后旧数据读取策略必须明确：只读兼容、归档、清理或回滚方案，不能留下无人负责的双写不一致。

## 回滚验收

- 每个变更必须提供回滚触发条件、回滚命令、预计影响、数据备份位置和回滚后验证命令。
- `app_store` 拆表回滚需证明旧读路径可恢复或兼容层可接管。
- 对象存储/CDN 回滚需证明已有图片 URL 不丢失，新旧 URL 访问策略明确。
- 后台账号安全策略回滚不得导致管理员永久锁死或密码状态不明。

## 监控 / 备份恢复演练验收

- Nginx：需提供配置备份、语法检查、reload 结果、关键域名只读访问验证；不得触碰 `pomer.cn` 官网配置。
- MySQL：需提供备份命令、备份文件位置、校验方式、恢复演练结果和恢复后抽样查询。
- PM2：需提供服务名、进程状态、重启/回滚命令、日志路径、错误日志扫描结果。
- 监控：需覆盖 API 5xx、登录失败异常、上传失败、对象存储/CDN 访问失败、数据库备份失败、PM2 进程异常。

## 不可接受的假通过条件

- 只有计划、设计或口头说明，没有代码、接口、脚本或运行证据。
- 只在本地 mock / fixture 通过，却写成线上 `api.pomer.cn` 通过。
- 用完整 token、密码、cookie 或密钥写入文档。
- 用 `/uploads/` 临时路径冒充正式对象存储或 CDN。
- 只用手工上传的 `cdn-check.png` 证明 CDN 可访问，却没有验证后端上传接口返回 CDN URL、小程序上传、相册展示、分享图和后台上传业务链路。
- 只证明新增写入成功，没有证明旧数据迁移、回滚和残留扫描。
- 只检查 PM2 进程存在，没有检查接口、日志和错误率。
- 修改或重启 `pomer.cn` 公司官网相关 Nginx、PM2、目录或路由。
