# 酒桌判官迭代运营方案：精彩瞬间时间线与分享增长

更新时间：2026-06-15

## 1. 最终判断

酒桌判官后续迭代应从“酒局记账/判官主控”转为“全员精彩瞬间时间线”。核心不是让一个人持续点欠酒加减，而是让每位参与者都能在聚会中快速留下可回看的照片、梗文案和时间点，结束后生成酒局简报、分享图和局外榜单互动。

最终产品主线：

1. 开局：每位玩家可上传 1 张开场打卡照，形成本局打卡墙。
2. 进行中：所有玩家都能随时添加精彩瞬间，必须带时间戳，可配图、文案、标签和可见范围。
3. 辅助记录：欠酒、加酒、转盘继续保留，但降级为辅助事件；判官只负责这些低频工具，不拥有内容精选特权。
4. 结束：每位玩家可上传 1 张收尾照，系统生成按时间线展示的酒局简报。
5. 局外：玩家可用积分推举参与过的某局瞬间上榜，例如“今日最有梗”“今日最欠酒”“今日最精彩”。
6. 分享：用户点击生成分享图后，后台静默制作；制作完成后在个人页对应酒局列表提示。

## 2. 评论判断对比

| 批注方向 | 判断 | 最终方案 |
| --- | --- | --- |
| 每个玩家上传开场照片 | 采纳 | 每人 1 张开场打卡照，形成打卡墙 |
| 默认所有权限，可取消 | 采纳 | 可见范围和用途默认全选，用户可取消 |
| 上传入口需要刺激性说明 | 采纳 | 增加强行动文案，刺激用户补图、补梗、上榜 |
| 局外用积分推举某瞬间 | 采纳 | 做“局外推举”，消耗积分推举到今日榜 |
| 榜单类型要贴近瞬间 | 采纳 | 今日最有梗、最欠酒、最精彩、最有画面 |
| 是否加入拍卖 | 暂缓 | 拍卖可能破坏线下流程，不进 MVP |
| 未补图流程不完整 | 改造采纳 | 不阻止结束酒局，但未补全不能公开分享、上榜、收打赏 |
| 补全后才可推举上榜 | 采纳 | 上榜候选必须有图片、文案、授权、审核状态 |
| 所有人都能设名场面 | 采纳 | 所有人可添加时间线节点，必须带时间戳 |
| 首页展示进行中酒局 | 采纳 | 首页/判官入口展示“正在进行中的酒局”，一键返回抓瞬间 |
| 私密爆料 | 采纳但限制 | 支持仅指定本局成员可见，禁止进入公开分享和榜单 |
| 增加开场瞬间 | 采纳 | `nodeType=opening` |
| 去掉反转瞬间/事件 | 采纳 | 删除反转作为正式事件类型 |
| 不要判官精选 | 采纳 | 不做判官精选特权，改为本人授权 + 系统规则 + 审核 |
| 账户积分公平性 | 采纳 | 账户积分可累积，未使用不清零，不让玩家觉得亏 |
| 判官权重降低 | 采纳 | 判官只负责欠酒、加酒、转盘；精彩瞬间由全员共创 |
| 每人开场照选谁做简报 | 改造采纳 | 默认生成开场打卡拼图；封面可由系统按热度/清晰度生成 |
| 全量记录每个瞬间 | 采纳为方向 | 鼓励全量珍贵瞬间，但用低成本时间线承载 |
| 视频 | 延后 | 本版本不支持视频上传，保留入口提示“后续开放” |
| 分享图后台制作 | 采纳 | 点击生成后进入后台任务，完成后个人页提示 |
| 私密爆料时间线展示 | 采纳 | 不展示图片和内容，只写入“某某给某某发送了爆料” |
| 补全与二次审核 | 采纳 | 分享流程不断，后台二审图片是否与本局相关 |
| 打赏与积分奖励 | 采纳 | 打赏转为赠送积分，后台配置各榜单阶梯奖励 |
| 分享图时间线排版 | 采纳 | 分享图以时间线为主导，图片按事件时间排序展示 |

## 3. 核心产品原则

- 全员共创，不做判官内容特权。
- 时间线优先，所有精彩瞬间、欠酒、加酒、转盘都以时间线节点呈现。
- 图片增强记忆，文字只做补充。
- 不阻止线下聚会，不因用户未补图而卡住结束流程。
- 完整内容才可公开传播、上榜或获得打赏。
- 账户积分可视为有真实价值，不能设计成“用不完就亏”的消耗品。
- 手机中断是常态，所有草稿、上传、分享图生成都必须可恢复。
- 分享图以时间线为主导，所有事件图片按时间顺序排版，不做割裂的拼贴墙。

## 4. 一局完整流程

### 4.1 开局打卡

每位玩家进入酒局后，可上传 1 张开场打卡照。

推荐入口文案：

- “先拍一张，今晚这局才算正式开场。”
- “别空手入局，留一张你的开场证据。”
- “每人一张打卡照，结束后自动生成酒局封面。”

规则：

- 每人默认 1 张开场照，可替换，不鼓励反复上传。
- 默认授权用途全选：本局可见、进入简报、可生成分享图、可参与榜单。
- 用户可取消任一授权。
- 简报封面默认使用开场打卡拼图，不用纠结选谁的照片。
- 如果要单图封面，由系统按清晰度、完整度、互动数生成推荐，不交给判官特权决定。

### 4.2 进行中精彩瞬间

所有本局玩家都可随时添加精彩瞬间。

入口设计要求：

- 首页、酒桌判官首页、酒局历史页都要展示“正在进行中的酒局”。
- 用户点击后直接回到当前酒局时间线，优先展示“添加精彩瞬间”按钮。
- 添加瞬间不超过 10 秒：选图、写一句、选标签、提交。
- 每条瞬间自动记录时间戳。

推荐入口文案：

- “刚刚这一下，值得留证。”
- “别让这个梗只活 3 秒。”
- “拍下来，等会儿全桌一起笑。”
- “这一刻不上简报就亏了。”

瞬间类型：

| 类型 | 说明 | 是否可上榜 |
| --- | --- | --- |
| 开场瞬间 | 每人开局打卡照 | 可 |
| 气氛瞬间 | 合照、举杯、生日、桌面氛围 | 可 |
| 梗瞬间 | 嘴硬发言、跑调、救场失败、爆笑时刻 | 可 |
| 欠酒瞬间 | 与欠酒、加酒、转盘相关的节点 | 可 |
| 私密爆料 | 只给指定本局成员看 | 不可 |
| 收尾瞬间 | 结束合照、空杯、返程、残局桌面 | 可 |

明确移除：

- 不做“反转瞬间/反转事件”作为正式类型。
- 拍卖不进 MVP，避免破坏线下流程。

### 4.3 私密爆料

私密爆料用于满足熟人局的“只给某几个人看”的需求。

规则：

- 可选择 1 个或多个本局成员可见。
- 不进入公开分享图。
- 不进入运营精选榜。
- 不参与打赏。
- 不允许被二次转发到局外页面。
- 不在时间线展示图片、正文和私密对象完整名单。
- 对本局其他成员仅展示占位节点：“某某给某某发送了爆料”。
- 若接收对象为多人，展示为“某某发送了一条私密爆料”，避免暴露关系。
- 后台仍保留举报和下架能力。

### 4.4 辅助事件

判官权重降到工具层，只负责低频辅助记录。

MVP 保留：

- 记一笔欠酒。
- 记一次加酒。
- 进入转盘游戏。

暂不进入 MVP：

- 拍卖。
- 反转事件。
- 复杂积分竞价。

辅助事件也要写入时间线，并带 `createdAt`、`operatorProfileId`、`targetProfileId` 和一句可选说明。

### 4.5 收尾生成

结束酒局时，引导每位玩家可上传 1 张收尾照。

规则：

- 不强制所有人上传，不阻止结束酒局。
- 没有收尾照时，可以先生成草稿简报。
- 未补全的瞬间不能参与榜单、打赏和公开分享。
- 系统提示“还有 X 个瞬间未补图，补全后可推举上榜”。

推荐文案：

- “补上收尾照，这局才完整。”
- “今晚最后一张，给简报一个结尾。”
- “补完图片才能冲榜，别让名场面卡在草稿里。”

## 5. UGC 完整性规则

内容状态分为：

| 状态 | 可见范围 | 可做什么 |
| --- | --- | --- |
| 草稿 | 仅本人 | 继续编辑、删除 |
| 待补图 | 本局内弱提示 | 可补图，不可公开分享、上榜、打赏 |
| 已补全 | 本局可见 | 可进入简报 |
| 已授权 | 按授权范围 | 可生成分享图、可参与推举 |
| 二审中 | 本局可见，公开内容暂缓 | 管理员审核是否与本局相关 |
| 已审核 | 公开范围 | 可上榜、可获得积分打赏 |
| 已隐藏 | 不公开 | 仅保留后台审计 |

补全最低标准：

- 必须有图片。
- 必须有一句文案或系统默认文案。
- 必须有上传者。
- 必须有时间戳。
- 必须有可见范围。
- 上榜前必须通过审核。

分享与补全关系：

- 未补图不打断本局分享流程，分享图仍可生成。
- 未补图节点在公开分享图里不展示图片，只可展示时间线占位文案。
- 已补图但疑似与本局无关的图片进入后台二审。
- 管理员二审可判定：通过、隐藏、要求重传、移出榜单候选。
- 被判定与本局无关的图片不可上榜、不可获得积分打赏、不可进入运营精选。

## 6. 局外推举与榜单

每位玩家都可在局外使用积分推举自己参与过的某局瞬间。

榜单类型：

- 今日最有梗。
- 今日最欠酒。
- 今日最精彩。
- 今日最有画面。
- 今日最佳开场。
- 今日最佳收尾。

推举规则：

- 只有“已补全 + 已授权 + 已审核”的瞬间可被推举。
- 推举消耗账户积分。
- 账户积分可现金获取，因此必须公平、可追踪、不可暗扣。
- 未使用积分保留到下次酒局，不清零。
- 推举失败或内容下架时，积分按规则退回或转成可用余额。
- 每人每日对同一瞬间推举次数应有限制，防刷。

积分打赏与榜单奖励：

- 上榜瞬间可获得“赠送积分”入口，不直接展示现金打赏。
- 积分奖励进入内容贡献者账户，也可按运营规则进入本局公共奖励池。
- 后台可为每个榜单配置不同阶梯奖励。
- 私密爆料、未授权内容、待审核内容不可获得积分打赏。
- 积分页需注明积分可用于兑换代驾、酒吧、餐厅等合作券或平台权益。

后台阶梯示例：

| 榜单 | 第 1 名 | 第 2-3 名 | 入围奖 |
| --- | --- | --- | --- |
| 今日最有梗 | 100 积分 | 50 积分 | 10 积分 |
| 今日最欠酒 | 80 积分 | 40 积分 | 10 积分 |
| 今日最精彩 | 120 积分 | 60 积分 | 15 积分 |
| 今日最有画面 | 100 积分 | 50 积分 | 10 积分 |

## 7. 分享图异步生成

分享页可能较大，不应要求用户等待现场渲染。

流程：

1. 用户点击“生成分享图”。
2. 服务端创建生成任务，状态为 `pending`。
3. 用户可离开页面，不阻塞继续使用。
4. 后台静默制作分享图。
5. 制作完成后，在玩家个人页的对应酒局列表外显示“分享图已生成”。
6. 用户点击后查看、保存、分享。

状态：

| 状态 | 说明 |
| --- | --- |
| pending | 已提交生成 |
| processing | 后台制作中 |
| ready | 可查看和分享 |
| failed | 生成失败，可重试 |
| expired | 过期需重新生成 |

分享图内容：

- 开场打卡拼图。
- 时间线主导内容。
- 今日最有梗候选。
- 本局欠酒/加酒辅助数据。
- 收尾照。
- 再开一局入口码。

时间线排版规则：

- 分享图以时间线为主导，按 `createdAt` 从开场到收尾排列。
- 开场打卡拼图作为顶部区块。
- 中间区块展示 3-6 个关键节点，优先包含有图片的精彩瞬间。
- 辅助事件使用小标签或一句话，不与图片节点抢主视觉。
- 私密爆料只显示占位文案，不显示图片和正文。
- 收尾照作为底部区块，承接“一句话总结”和再开一局入口。
- 若图片过多，服务端按时间线 + 互动数 + 榜单候选权重自动筛选。
- 若图片不足，使用开场照、收尾照和文字节点补齐版面。

## 8. 视频策略

本版本先不支持视频上传。

处理方式：

- 上传入口可以展示“短视频名场面后续开放”。
- 数据结构预留 `mediaType=video`、`videoUrl`、`coverImageUrl`、`duration`。
- 当前仅允许图片。
- 后续灰度时再限制 3-10 秒短视频、异步上传、强审核。

不在 MVP 做视频的原因：

- 审核成本高。
- 弱网上传失败率高。
- 分享图生成复杂。
- 视频内容更容易涉及隐私和失态风险。

```json

  "nodeType": "opening",
  "mediaType": "image",
  "imageUrl": "/store/moments/xxx.jpg",
  "videoUrl": "",
  "coverImageUrl": "/store/moments/xxx-cover.jpg",
  "duration": 0,
  "caption": "今晚开场，先留证",
  "tags": ["开场打卡"],
```

字段说明：

- `isTimelinePlaceholder`: 是否只展示占位，不展示图片和正文。
- `secondaryReviewStatus`: `pending / approved / rejected / require_resubmit`。
- `rankingEligible`: 是否可进入榜单。
- `rewardEligible`: 是否可获得积分奖励。

## 10. 页面与入口

| 页面 | 迭代要求 |
| --- | --- |
| 首页 | 展示正在进行中的酒局，一键返回抓精彩瞬间 |
| 等待室 | 引导每人上传开场打卡照 |
| 进行中记录页 | 主按钮为“添加精彩瞬间”，辅按钮为欠酒/加酒/转盘 |
| 桌面模式 | 按时间线轮播精彩瞬间，弱展示欠酒辅助数据 |
| 结束页 | 引导上传收尾照，提示未补全内容 |
| 酒局简报页 | 时间线展示开场、瞬间、辅助事件、收尾 |
| 个人页酒局列表 | 显示分享图生成状态、待补图数量、可推举入口 |

| 积分页 | 注明积分可兑换代驾、酒吧、餐厅等合作券或平台权益 |

## 11. MVP 范围

第一阶段必须做：

- 每人 1 张开场打卡照。
- 全员添加精彩瞬间。
- 图片 + 文案 + 标签 + 时间戳。
- 可见范围默认全选，可取消。
- 私密爆料指定成员可见。
- 首页正在进行中酒局快捷返回。
- 欠酒/加酒/转盘辅助事件。
- 时间线版酒局简报。
- 收尾照。
- 未补全不可公开分享、不可上榜、不可打赏。
- 分享图后台异步生成。
- 个人页提示分享图完成。
- 私密爆料写入时间线占位，不展示图片和正文。
- 后台二次审核图片是否与本局相关。
- 榜单积分阶梯奖励配置。

第一阶段不做：

- 视频上传。
- 拍卖。
- 反转事件。
- 判官精选特权。
- 复杂图片编辑器。
- 自由公开广场。

第二阶段：

- 局外积分推举。
- 今日榜单。
- 打赏入口。
- 运营精选。
- 商业化权益。

## 13. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 用户不愿上传 | 开场打卡和上传入口使用刺激性说明，降低输入成本 |
| UGC 不完整 | 不阻止结束，但阻止上榜、公开分享和打赏 |
| 图片与酒局无关 | 后台二审，失败后移出公开分享、榜单和积分奖励 |
| 隐私争议 | 默认可取消授权，支持私密爆料和指定可见 |
| 判官权重过高 | 判官只保留欠酒/加酒/转盘工具 |
| 积分公平性 | 未使用积分保留，推举失败/内容下架按规则退回 |
| 分享图生成慢 | 后台异步生成，个人页提示完成 |
| 分享图排版混乱 | 服务端按时间线、互动数和节点类型自动筛选，固定顶部开场和底部收尾 |
| 视频风险高 | MVP 不支持，仅预留入口 |
