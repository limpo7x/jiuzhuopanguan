# 聚会记录师产品改版需求与整改派工

更新时间：2026-06-17

本文是“聚会记录师”改版总需求。旧“酒桌判官 / 精彩瞬间时间线”文档继续作为历史技术参考，但从本轮改版起，产品名、页面文案、主流程、UI/UX 目标和验收口径统一以“聚会记录师”为准。

## 1. 改版结论

当前真机测试已暴露出产品方向和界面体验问题：

- 产品定位过重游戏和裁判，和用户现在需要的“聚会记录、拍照、分享”不一致。
- 当前页面仍大量出现“酒桌判官”“玩法设置”“欠酒”等强游戏心智，改版后必须降权。
- 创建流程虽然表面是 3 步，但第二步仍强制玩法配置，用户无法在 3 步内自然完成“创建房间并开始拍照”。
- 已见元素超边界、底部按钮被截断、模板卡片横向露半张、单个列表过长、单列卡片过厚重等问题。
- 首页、工具箱、我的等页面存在非核心内容占比过大，记录和分享入口不够靠前。
- 2026-06-17 用户明确纠偏：酒桌记账 / 聚会账本不能消失，必须与拍照记录并存，并共同进入分享页和分享截图保存。

改版目标：

> 聚会记录师是一款轻量、卡通、潮流、好分享的聚会记录小程序。用户应能在 3 步内创建聚会房间并拍第一张照片，同时可并行记录酒桌记账 / 聚会账本，后续自动形成时间线、相册、账本高光和酷炫分享页。

## 4. 三步内创建房间并拍照

改版后默认路径必须满足：

1. 首页点击 `创建聚会`。
2. 直接创建聚会并记录当前实时时间，立即得到房间和邀请方式；轻量主题选择从默认链路移除。
3. 点击 `开始记录 / 拍第一张`，直接进入拍照或上传。

验收边界：

- 不得把玩法配置作为必填步骤。
- 不得要求用户先理解欠酒、惩罚、判官、积分才能开始记录。
- 不得让用户在创建阶段滚动长列表才能继续。
- 第 3 步必须能进入拍照/上传，不能只停留在邀请页。
- 默认房间名、人数、模板和权限必须可自动填充，用户只在需要时修改。
- 如果创建、加入、继续记录任一动作依赖登录，首页必须有可见登录入口，或点击对应主按钮时直接打开登录面板/登录动作；不得只弹 toast 后让用户寻找不存在的入口。

## 4.1 双主线并存：拍照记录 + 酒桌记账

用户已明确要求：酒桌记账功能不能被改版移除。后续 UI/UX、前端、接口、测试必须按“双主线并存”处理：

- 默认路径仍优先保证三步内创建房间并拍第一张照片。
- 酒桌记账 / 聚会账本作为并行核心能力存在，但不在首页常驻；进入本局后与记录、相册、分享同级展示。
- 酒桌记账包括但不限于欠酒 / 已喝 / 加酒 / 结算摘要 / 账本榜单等现有能力；文案可更轻量，但能力不能凭空消失。账本页不得用“保存关键事件”替代原有欠酒、加酒、编辑能力。
- 拍照记录与酒桌记账必须共同沉淀到分享页和分享截图保存，分享内容至少包含照片墙或高光图、账本高光、关键事件和聚会总结。
- 玩法配置仍不得成为创建和拍第一张照片的必填阻塞；账本可在创建后立即补充或从记录页快速进入。
- 分享页和分享截图保存是当前最高优先级页面，UI/UX 需按“酷炫、年轻、可保存、可转发”重新定义，不得只保留普通列表或旧海报壳。

## 4.2 2026-06-18 链路收缩与内容直显规则

用户最新确认以下规则，优先级高于旧截图和旧壳实现：

- 首页最近相册封面展示该聚会上传的第一张照片；无照片时才使用默认封面。
- 首页底部“聚会账本”入口改为“工具箱”，继续沿用旧酒桌判官工具箱能力；点击后进入工具箱列表，每个工具都必须可用。
- 个人中心去重入口，不得出现大量重复按钮，也不得让大多数入口都跳到相册。
- 我创建的聚会进入某个聚会简报后，简报内图片可点击查看大图，再点击大图返回简报。
- 全链路取消图片审核机制：图片上传后可直接展示，并直接参与相册、简报、分享页和保存分享图；仍需保留隐私、可见范围和举报/删除等后续治理能力。
- 创建聚会时间取当前实时时间，该时间可用于聚会列表中每个聚会项目展示。
- 创建聚会页直接去掉轻量主题选择，不再作为默认创建步骤。
- 邀请预览去掉“照片记录 + 聚会账本”整块模块，去掉“口令区域已预留安全区”模块。
- 口令加入状态去掉“分享给好友 / 分享到群 / 保存海报”按钮，仅保留加入状态和必要口令信息。
- 拍第一张上传成功后，点击保存照片应进入聚会进行中页面，不得返回首页。
- 拍照/上传后的说明文案最多收缩到 2 行；下方提供内置默认可选文案，用户点击即可填充，减少手动输入。
- 可见与授权栏目去掉“仅自己”；默认 4 个选项均选中。

## 7. UI/UX 设计硬性要求

UI/UX 负责人必须先基于真机素材做用户体验审计，再产出新版方案。

硬性要求：

- 三步内可创建房间并拍第一张照片。
- 主按钮永不超边界，最长文案必须在 375px 宽度内完整显示。
- 长列表超过 5 项必须拆分为分组、折叠、横滑、搜索或二级页，不得单列一直堆。
- 首页首屏只能服务 3 个动作：创建聚会、加入聚会、继续记录。
- 创建流程不得强制玩法设置；玩法模板只能作为可选高级配置。
- 酒桌记账 / 聚会账本必须有清晰入口，并与拍照记录共同导出到分享页和分享截图保存。
- 大卡片必须有最大高度和固定比例，不得让单个卡片吃掉半屏以上。
- 底部固定按钮必须预留安全区，不得遮挡内容。
- 文案统一使用“聚会、记录、相册、分享、回忆、好友”，避免默认使用“判官、欠酒、惩罚、裁判”。
- 视觉方向允许卡通、潮流、多巴胺色、贴纸感、轻插画，但文字必须清晰，按钮必须有足够对比度。
- UI/UX 如需要重配图，必须使用 `imagegen-frontend-mobile` 或 `imagegen` 生成 3 套多屏移动端方向，不得只写文字方案。

追加准出标准（2026-06-15 用户反馈）：

## 9. 第一阶段验收门槛

- 分享页和分享截图保存同时展示照片记录与账本高光。
- 每个屏幕都通过 375px、390px、414px 宽度边界检查。
