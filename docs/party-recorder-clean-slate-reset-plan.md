# 聚会记录师 Clean Slate 清空旧项目污染总控计划

日期：2026-06-18
负责人：Codex PM
状态：P0 已立项，禁止直接删除，先做清单、备份、分派和准入验收

## 1. 目标

用户已明确要求重新建立“聚会记录师”，清空历史项目留下的外壳、代码、功能、数据和资产，避免旧项目污染新项目。

本计划把当前工作从“旧壳上继续修补”升级为 Clean Slate 重建：

- 停止把旧“酒桌判官”外壳当作新版实现基础。
- 保留 `聚会记录师 全流程原型 初始构思` 作为新产品主流程基线。
- 将旧页面、旧功能、旧文案、旧数据、旧后台、旧分享图和旧测试残留统一纳入清空或隔离清单。
- 任何删除、线上清理、重建数据、静态资源替换都必须有备份、回滚和证据。

PM 不直接修改业务源码，不直接删除数据和资产；PM 只负责清单、准入、分派、验收和退回。

## 4. 清空准入规则

任何角色执行删除、替换、线上清理、静态资源覆盖前，必须先交付清单：

| 准入项 | 必须证据 |
| --- | --- |
| 删除清单 | 文件/目录/数据表/接口/资产路径，旧污染原因，是否有新替代 |
| 备份清单 | 本地备份路径、线上备份路径或 git commit/branch，可恢复方式 |
| 依赖检查 | `app.json` 路由、import/require 引用、接口调用、后台入口、测试脚本引用 |
| 重建清单 | 新页面、新接口、新数据模型、新资产、新文案对应关系 |
| 验证命令 | `rg` 旧词扫描、构建/typecheck、编码检查、微信开发者工具预览矩阵 |
| 回滚方式 | 回滚命令、数据恢复方式、静态资源恢复方式、负责人 |

没有以上证据，只能写“待清空 / 待隔离 / 待复核”，不得写“已清空”。

## 6. 验收口径

Clean Slate 第一阶段只能在以下条件同时满足后写“清空完成”：

1. 前端 `app.json` 不再暴露旧玩法主入口，用户可见页面不出现旧项目词。
2. 分享页和分享截图不复用旧长列表/旧战报布局，必须按新版短屏强视觉重建。
3. 聚会账本与拍照流程并存，且一同进入简报和分享截图。
4. 后端测试数据和后台静态资源有备份、可回滚、可复跑清理证据。
5. 微信开发者工具预览框能完成创建、拍照、记账、简报、保存分享图、分享回流主链路。
6. `rg "酒桌判官|判官|欠酒|惩罚|战报|裁判"` 对用户可见源码、数据、资产清单无未豁免命中。
