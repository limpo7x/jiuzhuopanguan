## 4. 风控审核口径

### 4.1 私密爆料

- `private`、`selected` 或私密可见范围必须选择至少 1 个本局成员。
- 指定成员必须属于当前酒局，非本局成员不能写入 `visibleProfileIds`。
- 上传者和指定接收者可见正文、图片、标签和接收列表。
- 非接收者只能看到占位节点，不返回正文、图片和完整接收名单。
- 私密爆料默认不可进入公开分享图、榜单、积分奖励和局外推举。
- 后台仍可查看必要审核信息并执行隐藏或举报处理，但普通前台页面不得泄露私密内容。

### 4.2 补全与公开资格

| 内容状态 | 风控结论 | 可公开分享 | 可上榜/推举 | 可获积分奖励 |
| --- | --- | --- | --- | --- |
| `needs_media` 待补图 | 允许留在本局时间线弱提示 | 否 | 否 | 否 |
| `complete` 但未授权分享/榜单 | 本局内可见，尊重授权 | 否 | 否 | 否 |
| 一审通过、二审待处理 | 本局可见，公开传播暂缓 | 否 | 否 | 否 |
| 一审和二审均通过 | 可公开传播 | 是 | 是 | 是 |
| 私密或指定可见 | 只按指定范围展示 | 否 | 否 | 否 |
| 隐藏、拒绝、要求重传 | 不公开，仅保留审计 | 否 | 否 | 否 |

后端资格必须以 `completionStatus + usageConsent + reviewStatus + secondaryReviewStatus + rankingEligible` 计算为准，前端不能自行放开入口。

### 4.3 后台审核动作

| 动作 | 适用场景 | 必填证据 | 状态影响 | 风控要求 |
| --- | --- | --- | --- | --- |
| `approve` | 图片与本局相关、无明显隐私或违规风险 | 原因 | `reviewStatus=approved`、`secondaryReviewStatus=approved` | 可进入公开资格计算 |
| `hide` | 内容不适合展示、涉及隐私争议、明显无关或举报属实 | 原因 | `reviewStatus=hidden`，清除上榜/奖励资格 | 已有推举应触发退款或失效 |
| `reject` | 内容不合格且不建议重传 | 原因 | `reviewStatus=rejected`，不可公开 | 仅后台审计保留 |
| `require_resubmit` | 图片不清晰、与本局无关但可修正、授权或素材需补充 | 原因 | `secondaryReviewStatus=require_resubmit`，不可公开 | 前台需给上传者补图/重传入口 |
| `remove_ranking` | 内容可留在本局但不适合榜单传播 | 原因 | `rankingEligible=false`、`rewardEligible=false` | 不一定隐藏内容，但必须退出榜单和奖励 |

所有强审计动作都必须写入 `system-operation-logs`，至少包含操作者、动作、目标、原因、时间、旧状态和新状态。

### 4.4 举报处理

| 动作 | 风控结论 | 状态影响 | 下一步 |
| --- | --- | --- | --- |
| `valid_hide` | 举报属实且内容应下架 | 隐藏被举报 moment，清除公开/榜单/奖励资格 | 测试复核前台 timeline、brief、榜单入口同步 |
| `invalid_keep` | 举报不成立或证据不足 | 保留内容，但举报记录标记已处理 | 保留处理理由，避免重复误处理 |
| `require_resubmit` | 举报反映素材问题，可由上传者修正 | 要求重传，暂停公开、榜单、奖励 | 前端补重传入口 |
| `remove_ranking` | 内容可留本局但不适合公开榜单 | 移出榜单候选，必要时退回推举积分 | 复核积分流水 |

### 4.5 分享图与榜单

- 分享图只允许使用服务端已校验的可见时间线节点。
- 私密占位、隐藏、拒绝、待补图、未授权、未二审通过内容不得进入公开分享图。
- 今日榜单只统计 `complete + ranking consent + approved + secondary approved + rankingEligible` 内容。
- 非本局成员不可推举。
- 同一用户同一 moment 同一 category 每天最多推举 1 次。
- 内容被隐藏、拒绝、要求重传或移出榜单后，active 推举必须失效并写积分退款流水。
- 榜单奖励发放必须幂等，重复触发只能跳过已发记录，不能重复发积分。

新版必须保留的 P0 安全底线：

1. 默认记录不等于默认公开，拍第一张照片后只能进入本聚会可见范围。
2. 私密、指定可见、未授权、待审、未二审、待补图、隐藏、要求重传内容不得进入分享页、分享图、公开相册或照片墙。
3. 分享页和照片墙必须服务端过滤，前端不能只靠隐藏按钮控制传播。
4. 局外访问分享页只能看到明确公开授权且审核通过的内容。
5. 举报、隐藏、要求重传、移出公开展示后，分享页、相册、照片墙必须同步下线对应内容。
6. 后台审核和举报处理必须保留 operationLogs；没有日志不得签真实通过。
7. 涉及推举、奖励、积分的旧 M5 风控仍有效，但在新版中降权，不得因为视觉降权而删除流水和幂等证据要求。

需要 UI/UX 明确表达的隐私提示：

- 拍照/上传页：显示“默认仅本聚会成员可见”，并提供“指定成员可见 / 允许加入分享页”的明确选择。
- 创建/邀请页：说明通过二维码加入的人可以上传照片，发起人可管理相册和公开分享内容。
- 相册页：对私密或仅部分成员可见照片显示可见范围标识，不展示完整接收名单给无权限用户。
- 分享页预览：在发布前提示“仅包含已授权且审核通过的照片”，并展示被过滤数量或状态摘要。
- 照片墙：标明“公开展示中”或“仅聚会内展示”，避免用户误以为只是个人相册。
- 举报入口：每张照片详情和公开分享页都要有可发现的举报入口，举报后显示已提交状态。

#### 6.21.1 页面 data 白名单

以下字段允许进入前端页面 data，但仍需按角色过滤；成员态页面 data 不得直接复用到局外分享页、保存图或分享回流。

| payload | 允许进入页面 data 的字段 | 使用边界 |
| --- | --- | --- |
| `brief payload` | `briefId`、`sessionTitle`、`sessionDateText`、`coverPhotoUrl`、`photoHighlights[]`、`albumCount`、`ledgerSummary`、`ledgerHighlights[]`、`briefSummary`、`eventHighlights[]`、`shareReady`、`shareTaskId`、`reportEntryVisible`、`viewerRole`、`permissionStateLabel` | 只允许使用展示字段和脱敏标签；`briefId/shareTaskId` 可在页面 data 内用于导航和调试摘要，但不得渲染到用户 UI 或 PNG |
| `live payload` | `sessionId`、`sessionTitle`、`memberCount`、`viewerRole`、`canUploadPhoto`、`canViewAlbum`、`canViewLedger`、`uploadState`、`photoNodes[]` 的安全展示字段、`ledgerSummary`、`privacyNotice`、`reportEntryVisible` | 成员页可有权限布尔值和安全展示状态；局外/未登录 live 回流只能看到公开壳和登录/加入引导 |

安全展示字段定义：

- 照片只允许 `imageUrl`、`thumbnailUrl`、`caption`、`takenAtText`、`displayAuthorName`、`isPublic` 的安全派生值。
- 账本只允许聚合文本：条数、结算完成提示、脱敏摘要；不得包含个人明细或流水。
- 权限只允许中文展示态，如“公开回忆”“成员可见”“已隐藏私密内容”；不得展示 raw 枚举。

#### 6.21.3 UI / PNG 绝对黑名单

以下字段不得进入用户 UI、分享海报、保存分享图、分享回流公开页，也不得被 canvas 绘制或作为二维码/短链参数裸露。

| 黑名单字段 | 禁止原因 |
| --- | --- |
| 完整 `token`、`jzp-user-token`、`Authorization`、session secret、cookie、storage 原文 | 账号接管和会话泄露风险 |

#### 6.21.4 前端字段消费要求

1. 前端页面必须从后端提供的 clean `brief/live/share payload` 白名单字段消费，不得把完整接口对象直接 `setData` 到页面。
2. 分享海报和保存 PNG 必须只读取 `share payload` 的 `safe*` 字段；不得从 live/brief 原始节点数组里二次拼图。
3. 页面 data 可保留测试定位字段，但 WXML、canvas、PNG、二维码参数不得渲染黑名单字段。
4. `permissionState`、`viewerRole`、审核/举报状态必须先映射为中文安全标签，再进入用户 UI。
5. 对 `photoHighlights`、`ledgerHighlights`、`eventHighlights` 进行二次防御过滤：缺 `isPublic`、待审、私密、隐藏、被举报、无授权时直接不渲染。
6. 清理旧玩法字段消费：任何 `judge/report/punishment/rankingReward/wineDebt` 旧字段不得作为新版页面主展示数据源。

#### 6.21.5 后端 / API 过滤要求

1. 后端必须分别输出 clean `brief payload`、`live payload`、`share payload`，其中 `share payload` 是最小公开子集，不允许依赖前端自行过滤。

3. `visibleNodes/filteredNodeIds/permissionState` 只能在测试或调试摘要中脱敏输出；生产用户接口应输出安全展示态和过滤提示。
4. 分享图生成服务必须只使用 `share payload`，并在生成前校验没有黑名单字段、没有旧玩法词、没有私密/待审/举报/隐藏节点。
5. 对局外/未登录请求，后端默认返回公开壳和脱敏摘要；未经授权不得返回成员账本明细、完整相册、成员身份映射或房间管理字段。
6. 后端需为测试提供脱敏反例摘要：公开、仅成员、私密、待审、被举报、已隐藏各至少一条样本，证明过滤前后数量和原因分类。

#### 6.24.1 `PR-UGC-DATA-BOUNDARY-008S-RISK-GATE` 运行态数据边界门禁

复核时间：2026-06-18。PM 对关键链路源码做静态扫描，未发现 `PR Seed`、`IT-MOMENTS`、`PR-BE-DB-LOGIN`、`openId`、`signature`、`brief not found`、`task failed` 直接出现在目标 WXML 可见文案；命中主要是清洗正则、TS 类型空值或历史文档。UGC 本轮只追加运行态 storage / page data 与 UI / PNG 的传播边界，不触发 DevTools，不跑线上，不写风控准出。

边界原则：

1. storage、page data、Network 摘要可为运行和测试保留必要原始字段；但用户 UI、分享截图、保存 PNG、公开分享页不得传播内部字段。
2. 测试样本名、测试身份、内部 ID、权限 raw 字段、接口错误原文若只存在于 storage/page data，且 UI/PNG 已清洗，可记为“运行态残留可接受但不得传播”。
3. 完整 token、`openId`、`unionId`、`signature`、接口鉴权材料和可识别用户身份字段，即使在测试报告中也必须脱敏；不得进入截图、公开文档或 PNG。
4. `brief not found`、`task failed` 等接口错误原文不得作为面向用户文案；阻断核心路径时按 P0，非阻断但可见按 P1。
5. 旧品牌主文案不得出现在用户 UI / PNG；历史文档或清洗规则命中不算外露，但页面传播命中即退回。

允许存在于 storage / page data 原始字段，但不得 UI / PNG 外露：

| 字段 / 关键词 | 允许范围 | UI / PNG 判定 |
| --- | --- | --- |
| `PR Seed`、`PR-BE-DB-LOGIN`、`IT-MOMENTS` | 仅限测试 storage、page data、清洗正则、历史样本或脱敏测试摘要 | 用户 UI / 分享截图 / 保存 PNG 出现即 P0 |
| `permissionState`、`filteredNodeIds`、`visibleNodeIds` | 可在 page data、接口联调摘要、测试报告中用于证明过滤；公开报告建议只给数量和原因分类 | 用户 UI / PNG 只能展示安全中文提示，如“已隐藏不可公开内容”；raw 字段名或节点 ID 外露即 P0 |
| 内部 `briefId/taskId/sessionId/profileId/momentId/nodeId` | 可在 page data 中支撑导航和测试定位；测试摘要必须截断或脱敏 | UI / PNG 出现完整 ID 即 P0；局外视角出现任何成员或节点 ID 即 P0 |

任何形态都需脱敏或禁止传播：

| 字段 / 关键词 | 门禁 |

#### 6.24.2 `PR-FE-UGC-LINK-CLEANUP-008Y-REMOVE-REVIEW-USER-FACING` 旧审核字段用户可见口径核查

复核时间：2026-06-19。限定阅读 `docs/runtime/pm-objective-coverage-20260619.md` 与队列 008Y 行：PM 覆盖审计指出“整体图片审核机制移除”仍未完全闭环，前端服务/组件仍保留 `reviewStatus`、`secondaryReviewStatus`、`pendingMediaCount` 等审核/待补图字段，需要确认是否仅为内部兼容，或仍会形成用户可见审核口径、待审状态、待补图阻塞或过滤逻辑。本节只更新 UGC 风控计划，不改源码、不改 PM 总进度/公告/队列，不写真机/上线/全链路通过。

适用边界：

1. 本节覆盖图片直显链路中的用户可见口径；若与旧章节中“审核通过后可公开”的历史口径冲突，以 6.24 和本节为准。
2. `reviewStatus`、`secondaryReviewStatus`、`pendingMediaCount` 可作为后端兼容字段、迁移字段、后台治理或测试摘要保留；前端不得把它们映射成用户可见审核态，也不得用它们阻塞上传后直显。
3. 图片是否进入用户链路应按隐私范围、分享授权、媒体是否可用、删除/隐藏/举报限制和局外权限过滤判断；不得再以“审核通过”作为相册、简报、分享页或保存图准入条件。
4. 仍可保留举报/删除/隐藏后的后置治理；这不是恢复前置审核机制。

P0 / P1 退回规则：

| 等级 | 触发条件 | 退回对象 |
| --- | --- | --- |
| P0 | 用户上传后，因 `reviewStatus/secondaryReviewStatus` 非 approved 或 `pendingMediaCount > 0` 导致照片不进入本局相册、简报、分享页或保存图候选 | 前端优先；若接口用户 payload 强制输出审核态作为展示准入，联动接口/后端 |
| P0 | 用户 UI、分享截图或保存 PNG 出现“待审核”“审核中”“审核通过后展示/可见/分享”“待审核照片不可分享”等前置审核阻塞文案 | 前端 |
| P0 | 分享页/保存图只展示“审核通过”照片，导致已授权且媒体可用的直显照片被过滤 | 前端 + 接口/后端，按过滤来源退回 |
| P0 | `pendingMediaCount` 被展示为“待补图数量”并阻塞相册/简报/分享/保存图，或让用户误以为上传成功后仍需审核/补图才能展示 | 前端 |
| P0 | 局外/未登录视角因审核字段泄露内部状态，如 `reviewStatus=pending`、`secondaryReviewStatus=require_resubmit`、`pendingMediaCount=1` | 前端；若来自接口用户 payload，联动接口 |
| P1 | 用户 UI 非阻断地出现“待补图”“待处理照片”“审核状态”等旧状态标签，但照片仍可按权限直显 | 前端清文案；不作为开发直显阻塞，但阻塞 UGC 准出 |
| P1 | 空态、过滤提示或分享说明仍写“仅展示审核通过照片”“暂无审核通过照片”等旧心智 | 前端/UIUX 清理 |
| P1 | page data 保留旧字段但测试无法证明 WXML/canvas 不渲染，或无法证明分享图未使用旧字段过滤 | 测试补证；前端补字段消费说明 |

内部兼容字段可保留的条件：

| 字段 | 可保留位置 | 禁止用途 |
| --- | --- | --- |
| `reviewStatus` | 后端兼容、后台治理、测试摘要、page data 调试字段 | 禁止作为普通用户展示准入、状态标签、分享图过滤条件或 PNG 文本 |
| `secondaryReviewStatus` | 后台治理、历史数据迁移、测试定位 | 禁止映射为“待二审/待补图/要求重传后才可见”等用户态 |
| `pendingMediaCount` | 后台统计、测试摘要、内部排障 | 禁止展示给普通用户；禁止阻塞已上传媒体直显和分享候选 |
| `needs_media` / `require_resubmit` 历史态 | 仅历史兼容或后台治理 | 禁止作为新直显链路的用户可见主状态；若媒体不可用，只能显示中性失败/不可用提示 |

需要前端清理的用户可见文案 / 状态清单：

| 清理对象 | 退回口径 |
| --- | --- |
| “待审核”“审核中”“审核通过”“审核通过后可见/展示/分享/保存” | 全部清理出普通用户 UI、分享页和保存 PNG |
| “待补图”“待补充图片”“补图后展示”“要求重传后可分享” | 新直显链路不得作为用户主状态；媒体不可用时改为中性上传失败/图片不可用 |

| raw `reviewStatus`、`secondaryReviewStatus`、`pendingMediaCount` 字段名或枚举值 | 不得出现在 UI、PNG、局外/未登录页面；page data 可保留供测试，但需证明未渲染 |
| “pending/approved/rejected/require_resubmit/needs_media” 英文字段态 | 不得作为用户可见文案；测试摘要需脱敏说明 |

需要测试覆盖的核查口径：

| 测试点 | 判定 |
| --- | --- |
| 上传成功后进入本局进行中 / 相册 / 简报 / 分享页 | 不得出现审核等待；照片按隐私和授权直显 |
| 分享页和保存 PNG | 不得出现审核/待审/待补图文案、raw 字段名或枚举值；不得因未 approved 过滤已授权照片 |
| page data / storage | 可含旧字段，但 UI/PNG 已清理且截图/OCR 无命中，记为内部兼容可接受 |
| 删除 / 举报 / 隐藏 | 可以触发后置移除或占位；不得包装成前置审核流程 |
| 局外 / 未登录 | 只看授权公开内容或登录/加入提示；不得看见审核 raw 状态或 pending 计数 |

仍需证据：

| 责任角色 | 必须补齐 |
| --- | --- |
| 前端 | 静态扫描 `reviewStatus/secondaryReviewStatus/pendingMediaCount/待审核/待补图/审核通过` 的用户可见命中清单；说明哪些仅内部兼容；补 album/brief/share/share-poster WXML/canvas 不渲染证明 |
| 测试 | DevTools 预览框受控复测：上传后直显、相册、简报、分享页、保存 PNG、局外/未登录；OCR/关键词扫描；page data 与 UI 对照 |
| 接口/后端 | 若用户 payload 仍输出旧审核字段，需说明是否仅兼容；不得要求前端以 `approved` 作为直显/分享准入 |

当前 UGC 结论：`PR-FE-UGC-LINK-CLEANUP-008Y-REMOVE-REVIEW-USER-FACING` 已建立风控侧核查口径。旧审核字段可以内部兼容保留，但用户可见文案、状态标签、空态提示、分享过滤和保存 PNG 不得再表达“审核/待审/待补图/审核通过后展示”。缺前端清理证据、测试截图/OCR、page data 与 UI 对照前，不写真机、上线、全链路或 UGC 准出。
